Checking Docker Images and Containers
```sh

```
```sh
docker container ls  # Alternative to 'docker ps'

Running Containers

```

docker run -d -p 8080:8080 --name tomcatcontainer tomcat:latest

```sh
netstat -tunlap
```
If `netstat` is not available, install it:
```sh
sudo apt install net-tools

```

Inspecting a Running Container
```sh
docker exec tomcat ls /usr/local/tomcat/webapps   # No host folder in the latest version
```
```sh
docker exec tomcat java -version  # Check Java version inside the container
```

Removing and Restarting a Container
```sh

```

Docker Objects

Summary of Docker Objects
- **Containers**: Running instances of images.
- **Images**: Read-only templates used to create containers.
- **Volumes**: Persistent storage for container data.
- **Networks**: Facilitate communication between containers and external systems.
- **Registries**: Storage and distribution points for images.
- **Dockerfile**: Defines how to build a Docker image.
- **Docker Compose**: Manages multi-container Docker applications.

---

What is Docker Build Context?
In Docker, the **build context** is the set of files and directories that are available to the Docker engine when building a Docker image. 
The build context includes the `Dockerfile` and any files required for the image build process.

Practical Session: Understanding Docker

Step 1: Verify Docker Installation
```sh
docker --version
```

Step 2: Clone a Sample Web Application
```sh
git clone https://github.com/kkeducation12345/maven-web-app-project-kk-funda.git
cd maven-web-app-project-kk-funda
```

Step 3: Install Maven and Java
```sh
sudo apt install maven -y  # Installs Maven and JRE
java --version  # Verify Java installation
mvn -version  # Verify Maven installation
```

Step 4: Build the Application Artifact
```sh
mvn clean package
```
Ensure your `pom.xml` contains a valid Maven build configuration:
```xml
<build>
    <plugins>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-war-plugin</artifactId>
            <version>3.3.2</version> <!-- Use a stable version -->
        </plugin>
    </plugins>
</build>
```

Step 5: Create a Dockerfile
```sh
vi Dockerfile
```
Add the following content to the Dockerfile:
```dockerfile
FROM tomcat:9.0.100
COPY target/maven-web-application.war /usr/local/tomcat/webapps/maven-web-application.war
```

Step 6: Build the Docker Image
```sh
docker build -t kkeducation12345/java-web-app .
```

Step 7: Verify Docker Images
```sh
docker images  # OR
```
```sh
docker image ls
```

Step 8: Push Image to Docker Hub
**Before pushing, authenticate to Docker Hub:**
```sh
docker login -u kkeducation12345 -p password
```
Push the image:
```sh
docker push kkeducation12345/java-web-app
```

Step 9: Run a Container from the Image
```sh
docker run -d -p 8080:8080 --name javawebapp kkeducation12345/java-web-app
```

Step 10: Verify Running Containers
```sh
docker ps -a  # Lists all containers
```

# Accessing a Running Container
To enter the running container's shell:
```sh
docker exec -it javawebapp /bin/bash
```

1. Docker Architecture
The three main parts shown are:
Docker Client  →  Docker Host  →  Docker Registry
                     │
                     ├── Docker Daemon
                     ├── Images
                     └── Containers
Docker Client
The Docker Client is what you interact with from the terminal.
For example:
docker run nginx
docker build .
docker pull nginx
docker ps
When you type:
docker run nginx
the Docker Client doesn't actually create the container itself.
It sends a request/API request to the Docker Daemon.

2. Docker Host
The Docker Host is the machine where Docker is installed and where containers actually run.
In your example, it is the:
EC2 Ubuntu instance
Inside that EC2 machine, you have the Docker Daemon:
EC2 Ubuntu
│
└── Docker
    │
    └── Docker Daemon (dockerd)
         │
         ├── Images
         ├── Containers
         ├── Networks
         └── Volumes
Docker Daemon

The Docker Daemon is the main background service that does the actual Docker work.
It receives requests from the Docker Client and performs them.
For example:
docker run nginx
means approximately:
You
 │
 │ docker run nginx
 ▼
Docker Client
 │
 │ API request
 ▼
Docker Daemon
 │
 ├── Is nginx image available?
 │
 ├── If not → download it
 │
 ├── Create container
 │
 └── Start container
 
3. Docker Registry
A Docker Registry is a place where Docker images are stored.
For example:
Docker Hub is a public registry.
Suppose your EC2 machine doesn't have the nginx image.
You execute:
docker run nginx
Docker checks:
Do I already have nginx image?
       │
   ┌───┴───┐
   │       │
  YES      NO
   │       │
   │       ▼
   │   Pull from
   │   Registry
   │       │
   └───┬───┘
       ▼
   nginx image
       │
       ▼
   Create container
       │
       ▼
   Start container

That's exactly what you saw in your screenshot:
Unable to find image 'nginx:latest' locally
Pulling from library/nginx
...
Status: Downloaded newer image for nginx:latest
The important point is:
The registry stores images; the Docker Host runs containers.

4. Docker Workflow
The picture gives:
Dockerfile → Docker Image → Docker Container
This is extremely important.
Dockerfile
A Dockerfile is like a recipe/instruction document.
For example:
FROM openjdk:17
COPY app.jar /app.jar
CMD ["java", "-jar", "/app.jar"]

It tells Docker:
Start with Java 17, put my application inside, and run it.
Docker Image
When Docker processes the Dockerfile:
docker build .
it creates an image.
Think:

Dockerfile
   │
   │ docker build
   ▼
Docker Image
An image is basically a prepared package/template containing what is needed to run your application.
Docker Container
When you execute:
docker run myimage
Docker creates a running container from that image.
So:
Dockerfile
     ↓
 Docker Image
     ↓
 Docker Container

A simple real-world analogy:
Recipe       → Dockerfile
Prepared food → Docker Image
Food being served → Docker Container
The analogy isn't technically perfect, but it's useful for remembering the relationship.

6. What does -d mean?
-d
means detached mode.
The container runs in the background.
Without -d, your terminal can remain attached to the container's output.
With:
docker run -d nginx
Docker starts NGINX in the background and gives you your terminal back.

7. What does -p 80:80 mean?
This is very important.
-p 80:80
means:
Host port : Container port
     80   :      80

So:
EC2 Host
Port 80
   │
   │
   ▼
NGINX Container
Port 80
When someone accesses:
EC2-IP:80
the request is forwarded to:
NGINX container:80
That's why you could see:
Welcome to nginx!
in the browser.

8. What does --name nginxcontainr mean?
--name nginxcontainr
gives your container a human-readable name.
Instead of remembering a container ID such as:
081d763d11e1...
you can use:
nginxcontainr
For example:
docker stop nginxcontainr
or:
docker start nginxcontainr
