Docker Networks
===============

--> Docker networks are used to establish communication between containers.
--> If both the containers are same network we can establish the connection.
--> If you are not mention any network, while creating a container, It will be created in "default bridge network".
--> By default docker have three networks

     1. bridge [default]
     2. host
     3. none

How to list a docker networks?
------------------------------

docker network ls

How to see the container is created in which network?
------------------------------------------------------

docker inspect <cid>


How to check both the containers are connected or not?
-------------------------------------------------------

step 0: create a two containers.

step 1: go inside the container one

docker exec -it mavenwebapp /bin/bash

step 2: ping with another container ip

yum update
yum install -y iputils




ping 172.17.0.3

curl -v telnet://172.17.0.3:8080

NOTE: In default bridge network only ip's will work to connect another container not a container names.

Dis advantage of bridge n/w: If container restarted we are not guarantee to get same IP




IQ] what is the difference between default bridge network and custom bridge network?

Ans: Incase of default bridge network the communication can happen through only IP address. Where as in custom bridge network the communication can happen through the IP address/ container name.


How to create a network in docker?
----------------------------------------

Syntax: docker network create -d <driver> <networkname>

EX: docker network create -d bridge jionetwork
docker network ls

How IPs are allocating to container?
------------------------------------
docker inspect <network-name>

How to remove a unused networks?
--------------------------------

docker system prune or docker network prune  or docker network rm <nwtwork-name>

What is docker host network?
----------------------------

If we create container in host network, Container will not have an IP address.

NOTE: We can not create more than one container with same container port in the host network.

NOTE: you can not create custom host network like bridge


EX: docker run -d --network host --name javawebapp kkeducation123456/maven-web-app:1.2
    
     docker inspect 1ef68b5d5d80



=========================================================================================

What is none network?
---------------------

--> If you create containers in none network, Container will not have an IP address.
--> we can not access these containers from outside or from any containers or internally.

NOTE: The scope of the bridge/host/none with the docker server only, To overcome this problem we are using "overlay" network [multi host networks]

Introduction
In the world of containerization, Docker networking plays a vital role in enabling
communication between containers, services, and the outside world. Whether you're building
simple applications or managing complex microservices architectures, understanding how
Docker containers interact over different network types is key to building secure, scalable,
and reliable environments.
This guide walks you through:
. The importance of Docker networking
. Key Docker network types like bridge, host, none, and custom networks
. Testing with containers using default and custom bridge networks
. Using container names for communication with Docker's internal DNS
. Steps to connect containers to multiple networks
. And finally, pushing Docker images to AWS Elastic Container Registry (ECR)-a secure and
scalable way to manage your container images in the cloud.
Why is Docker Networking Important?
Docker networking plays a crucial role in containerized environments. It ensures that:
. Containers can talk to each other (communication).
. Containers can access the internet.
. You can control the visibility and isolate services.
When working on microservices, proper networking ensures that your services are discoverable,
secure, and scalable.
Containers Have Their Own IP Addresses
Yes! Every Docker container gets its own private IP address within the network it belongs to. This
IP is:
. Unique within the Docker network
. Assigned dynamically by Docker's internal DNS system
. Can be seen using docker inspect <container>
This IP allows containers to talk directly to each other-even without exposing ports to the host.
In Docker, we have three networks:
· bridge
. host
none
1. Bridge (Default)
. This is the default network driver.
. When you create a container without specifying a network, it goes into the default
bridge network.
. Containers can talk to each other using IP, but not by name unless it's a custom bridge.

use ping to reach two from one
. ping sends ICMP Echo Request packets to the specified IP address.
. If the target container is running and connected to the same network, it replies with ICMP
Echo Reply packets.
. This confirms network-layer connectivity (i.e., the containers can see each other over the
network).
Note:
. ping uses ICMP (Internet Control Message Protocol), not TCP or UDP.
. It operates at the network layer (Layer 3) of the OSI model.
. It does not check if a specific port or service is running, only if the host is reachable.
